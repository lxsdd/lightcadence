# LightCadence product operating rules

One product, one consolidated draft, one autonomous development task. GitHub is the source of truth. The owner-authorized private specification v0.1 and private project record govern product decisions. Use the current registered alternating claim=null route; pause the corresponding task and verify that its running invocation has ended before manual source publication. Read the live draft/ref/HEAD; write complete trees against the exact parent using a non-forced expected-HEAD ref update; read back. Do not touch main, other projects, other claims, merges, releases, tags or paid services. Report actual product changes and exact-SHA CI, not plans as delivery.

Native Home Assistant integration (authentication, permissions, configuration, panel, device registry, coordination), separate local asyncio/Python engine (monotonic scheduling, DSP, rendering, sessions, transport), one responsive Lit/TypeScript UI. One writer/lease per physical device, independent disjoint zone sessions, explicit overlap conflict and handover. Manual intervention detaches that device; stop/restore must not undo its subsequent manual state. Server-authoritative revisioned sessions, reconnect without restart, idempotent requests, invalidate queued frames on stop, no stale replay. Stable device identities independent of IP; one versioned data model for floorplan, zones, scenes, effects and timeline. No arbitrary lamp count, session time or performance caps. Bounded mailboxes and measured device-specific cadence are required. No hardcoded household details.

Use existing qualified components after provenance and license review. No OEM code, firmware, credentials, household topology, private data, real device identifiers, private source snapshots or restricted assets in public Git history, CI logs or artifacts. No license grant or distribution decision is implied by public development. No real device, scene or user data writes without explicit appropriate permission. No public engine port or exposed secrets; least privilege. Offline/synthetic tests cannot establish hardware operation.

Adopt shared CI qualification and UI runtime rules: FAST push/PR (original positive and negative tests, compile/type checks, appropriate production UI wiring, standard Linux runners, least privilege, pinned dependencies/actions, no artifact upload; cancel superseded runs); FULL deliberate exact-commit software/runtime qualification; CANDIDATE immutable hashes after rights and owner approval; RELEASE only verified identical candidate bytes after owner approval, never rebuild. No candidate or release publishing at this stage. Separate actual HA runtime, real UI, real LAN/BLE and hardware evidence from synthetic results. Keep device I/O disabled in automated tests. Update private record at milestones. Never claim hardware behavior from socket send, mock or simulation.

First vertical delivery: real engine, HA config flow and panel, selection, rainbow/scanner/pulse, independent sessions, start/stop/restore and device handover, reconnect, qualified Chroma output; real acceptance remains owner-controlled. Subsequent DSP, floorplan, timeline and additional devices use the same contracts, not parallel implementations.

## Shared responsive HA workspace standard

Use the owner-approved adaptive dashboard design principle across every LightCadence view. The actual available HA content container (after sidebar, header and other shell chrome) determines layout, not the window/viewport width. Consume available width and definite height without arbitrary maximum content width, artificial vertical space or fixed viewport subtraction. Align desktop columns at both top and bottom; use proportional, stacked sections on narrow containers, including tablet, smartphone, rotation and sidebar changes. Do not clip controls or introduce hidden/nested scrolling; allow natural outer-page vertical scroll if the content cannot fit. Preserve HA theme variables, accessible text states in addition to colors, touch targets and keyboard focus. Reuse the shared workspace layout for live control, scenes, effects, floorplan and timeline; independently validate specialized interactive editors. Test the real bundled UI under changing parent dimensions at fixed viewport, wide desktop, tablet, narrow phone and short landscape, including long content. Layout tests in a synthetic HA-like shell are not real Companion/HA-device acceptance.
