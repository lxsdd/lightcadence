# Opt-in saved-show switches

For an explicitly enabled physical candidate, HA integration Options lists saved non-audio scenes. Select only the scenes to expose. No switch is created by default; preview never creates switches. HA stores stable scene UUID references in integration options; the engine remains the scene/session authority. No restart/reload, options change, polling, or entity restoration starts or stops a session.

The switches use the existing native start_scene/stop_scene actions and caller context. Only administrators and HA-owned system contexts can operate them. On is a request to start the current saved scene revision if no matching active session exists; off stops the uniquely matching saved-scene session. Duplicate on/off are no-ops; ambiguity is unavailable. A deleted scene can still stop its active session, then becomes unavailable. All switches share a five-second state poll, with immediate reconciliation after action; engine failure is unavailable rather than false/off. Already submitted device frames and restore uncertainties retain existing behavior. No ordinary HA light interception.

Audio scenes require a separately selected live source and are not exposed by this initial options flow. Saved scene edits affect a subsequent explicit start, not a running show. The switch uses the existing default saved-scene launch without spatial-path overrides. Removing a selected reference removes its live entity after reload; an HA registry entry may remain unavailable. No stop is implied. Manually expose selected entities in the existing Google Home integration only after hardware acceptance; no cloud exposure or configuration is performed automatically. Google Home caller-context compatibility requires real acceptance, not a guarantee.
